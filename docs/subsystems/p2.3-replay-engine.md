# Subsystem: Deterministic Replay Engine

## Status

- Design: **ACCEPTED BASELINE**
- Implementation: implemented
- Verification: passed
- Authorized milestone: P2.3

## Purpose and boundary

`ReplayEngine` executes a validated capability through the shared `ActionGateway`, collects semantic snapshots through `SnapshotCollector`, and delegates state interpretation to `StateEvaluator`. It does not import model providers, discovery, or browser mechanics directly.

```
ValidatedCapability
      |
ReplayEngine
  | input/profile preflight
  | ActionGateway dispatch
  | bounded semantic re-observation
  | StateEvaluator
  ` ReplayResult
```

## Retry interpretation

`retry_policy` on a completed side-effecting step means retry observation only. The engine must not repeat the original side effect while waiting for state to settle.

For the current capability fixture, the search step uses `retry_policy` plus a semantic postcondition so the engine can observe the results page until it becomes visible, then continue to later steps. `MEMBER_NOT_FOUND` still stops the replay immediately once the business outcome is observed.

If the observation budget is exhausted before the step becomes ready, the engine returns `STEP_TIMEOUT`.

## Result mapping

The engine returns structured replay failures for preflight problems, gateway denials, control-state rejections, target resolution errors, and uncertain surface effects. `ACTION_EFFECT_OCCURRED_EVIDENCE_FAILED` remains a failure and is not retried as a side effect.

`ReplayEngine` does not emit its own evidence writer seam in this milestone. Evidence stays on the gateway path, which redacts sensitive fill values before persistence.
