# Subsystem: Evidence Recorder

## Status

- Design: **ACCEPTED BASELINE**
- Implementation: `implemented`
- Verification: `passed`
- Authorized milestone: `P1.2`

## Before implementation

### 1. Problem

Persist structured evidence for a run without carrying raw secrets or arbitrary runtime objects into durable storage.

### 2. Input and output contract

Typed `EvidenceEvent` input, runtime redaction context, and JSONL output under an injected evidence root. Unknown fields are rejected by the event contract. Overlong summaries are rejected by the contract. The recorder returns a small write reference with the persisted path and event id.

### 3. State and dependencies

Owns a local run evidence directory and one JSONL stream per run. Depends on the evidence contract and redaction helpers. It does not depend on browser, provider, policy, replay, or orchestration layers.

### 4. Accepted direction

Uses the accepted initial JSON artifact storage direction from ADR-008 with a narrow file-based sink and explicit redaction before persistence.

### 5. Alternatives considered

A logging framework with ad hoc extras and a database-backed event store were both deferred because the milestone needs a small inspectable prototype rather than infrastructure.

### 6. Costs and failure modes

File-based persistence is single-process oriented and does not provide transactional or multi-writer guarantees. Exact-value and key-based redaction do not semantically discover arbitrary PII. Richer failure attachments remain out of scope until a later subsystem.

### 7. Boundary and assumption tests

Tests cover JSONL persistence, append behavior, identifier correlation, explicit sensitive-value redaction, sensitive-key redaction, rejection of unsupported objects, summary length rejection, path traversal rejection, and import side-effect freedom.

## After implementation

### 8. Actual files and behavior

- `src/capability_runner/contracts/evidence.py`
- `src/capability_runner/evidence/__init__.py`
- `src/capability_runner/evidence/redaction.py`
- `src/capability_runner/evidence/evidence_recorder.py`
- `tests/unit/evidence/test_evidence.py`

Evidence events are written as UTF-8 JSON Lines under a configured evidence root. Sanitization happens before write. Sensitive wrappers, sensitive keys, and explicit values are redacted to `[REDACTED]`.

### 10. Known limits and next integration

This is a single-process JSONL prototype. It does not provide browser screenshots, crash-proof audit logging, multi-writer safety, or semantic PII discovery. The next authorized integration point is later failure-evidence wiring through a safe attachment path.
