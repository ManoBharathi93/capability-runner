# Subsystem: P4.1 Same-Session Human Handoff

## Who may act in the session

Pause automation, make ownership explicit, and reject stale requests. Keep the same session across takeover.

For current behavior, use [the product guide](../submission/test-product.md) and
[progress](../progress.md). The record below preserves the decision, tests and
limits at this subsystem's implementation date. Earlier phase restrictions and
operator-control descriptions are historical; the
[native handoff record](direct-browser-handoff.md) explains the later physical-input exception.

## Before implementation

### 1. Problem

Automation must be able to pause, let one authorized operator act on the same live surface session,
and resume only after fresh state validation. Automation and operator actions must never overlap or
use stale ownership generations.

### 2. Input and output contract

`InterventionRequest` identifies the intervention, original run, control session, opaque
`SurfaceSessionRef`, and safe reason. `InterventionRecord` immutably captures that request and the
generation at which pause was requested. `InterventionResult` reports typed lifecycle outcomes,
safe reason codes, the record, and current session state. `ResumeValidationResult` reports `VALID`
or `INVALID` from an injected asynchronous validator.

`InterventionManager` exposes asynchronous request, grant, return, validation, and stop methods.
`OperatorActionGateway.execute` accepts the existing typed gateway action/context plus an explicit
operator identity and returns the existing `GatewayResult` contract.

### 3. State and dependencies

Session Controller remains authoritative for lifecycle, owner, generation, and the shared dispatch
lock. Intervention Manager owns only in-memory intervention records. Browser Surface Adapter owns
the live context/page behind the opaque surface reference.

Intervention code may depend on contracts, Session Controller, Policy Guard, the abstract
`SurfaceAdapter`, and a narrow evidence writer. It must not import Browser Surface Adapter,
Playwright, Discovery, Replay, Model Client, or provider modules.

### 4. Accepted direction

ADR-003 requires all surface actions to pass through policy, ownership, and evidence controls.
ADR-006 requires explicit ownership transfer, stale-action rejection, and same-live-session human
control. P4.1 applies those decisions by adding a symmetric operator dispatch path under Session
Controller's existing lock and by delegating every lifecycle transition to Session Controller.

### 5. Alternatives considered

A replacement browser session was rejected because it would not be a same-session handoff. Direct
operator calls to the surface adapter were rejected because they would bypass Policy Guard,
generation checks, mutual exclusion, and evidence.

### 6. Costs and failure modes

Intervention records are process-local and are not durable across restart. Operator authentication,
transport, disconnect detection, frontend controls, and engine continuation are not implemented.
Resume validation is injected by the caller and must freshly inspect the current surface; an
`INVALID` result leaves automation blocked in `resume_requested`. Evidence records high-level safe
events and explicitly redacts fill values; it does not persist raw browser state.

### 7. Boundary and assumption tests

The acceptance matrix covers immutable records, valid and invalid lifecycle transitions, original
automation-owner restoration, stale generations, terminal sessions, wrong operators, policy and
binding denial, sensitive fill-value redaction, bidirectional dispatch races using `asyncio.Event`
barriers, forbidden imports, and a real Chromium handoff on one opaque surface session.

## After implementation

### 8. Actual files and behavior

- `src/capability_runner/contracts/intervention.py` defines immutable intervention and validation
  contracts.
- `src/capability_runner/contracts/sessions.py` includes the explicit `NOT_OPERATOR_OWNER` error.
- `src/capability_runner/interaction/session_controller.py` preserves the original automation run
  owner, serializes operator and automation dispatch through one lock, rejects return while an
  operator action is in flight, and advances generation on pause, grant, stop, and resume.
- `src/capability_runner/intervention/intervention_manager.py` coordinates request, quiescence,
  grant, return, fresh validation, resume, stop, and sanitized lifecycle evidence.
- `src/capability_runner/intervention/operator_action_gateway.py` applies trusted binding lookup,
  Policy Guard, operator ownership/generation checks, surface dispatch, and redacted evidence.
- Unit, architecture, and real-browser tests live under `tests/unit/intervention/`,
  `tests/architecture/`, and `tests/integration/intervention/`.

No Discovery, Builder, Replay, provider, Browser Surface Adapter, frontend, or operator UI code was
changed.

### 10. Known limits and next integration

P4.1 provides backend handoff mechanics only. There is no HTTP/operator transport, authentication,
frontend, persistence, reconnect behavior, Discovery continuation, or Replay continuation. Those
remain outside this authorization. P2 and P3 stay frozen, and no later P4 or P5 work may begin
without separate owner authorization.
